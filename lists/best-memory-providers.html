Best Memory Providers for Hermes Agent

The top community-built memory and context management tools for Hermes Agent, ranked by GitHub stars. Memory is what makes Hermes self-improving — these tools extend its built-in recall with long-term semantic memory, graph-based retrieval, and cross-session persistence.

For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

Mem0 is a universal memory layer for AI agents and an official Hermes Agent memory provider, available as a managed cloud service or self-hosted open-source software under Apache-2.0. It supports semantic, keyword, and entity-based retrieval, with SDKs, a CLI, and a self-hosted server.

vectorize-io / hindsight

Hindsight provides long-term agent memory through retain, recall, and reflect operations. It supports hosted and local LLM providers and can be deployed with Docker, pip, or Kubernetes.

volcengine / OpenViking

OpenViking is an open-source context database and official Hermes Agent memory provider that organizes resources, memories, and skills as files. It supports scoped semantic search across directories, archives sessions, and extracts inspectable Markdown memories.

topoteretes / cognee

Cognee is an open-source memory platform for giving agents persistent long-term memory across sessions with a self-hosted knowledge graph engine. It structures text as entities, relationships, and searchable chunks, and supports custom data models, ontologies, plugins, and MCP.

supermemoryai / supermemory

Supermemory is a memory engine and API, and an official Hermes Agent memory provider, that extracts conversation facts, handles contradictions, and automates forgetting. Its listed connectors include Google Drive, Gmail, Notion, OneDrive, and GitHub, and it processes PDFs, images, videos, and code.

garrytan / gbrain

Gbrain is an opinionated brain for OpenClaw and Hermes Agent that stores facts with provenance and supports corrections and withdrawal. It shares memory across agents while keeping transient task state local, with optional semantic search, synthesis, and background enrichment.

plastic-labs / honcho

Honcho is a memory library for building stateful agents that tracks peers, sessions, and messages over time. It offers Python and TypeScript SDKs and supports managed, local, and self-hosted use.

campfirein / byterover-cli

ByteRover CLI treats memory as a Git repo, using a plain Markdown context tree with Git-like commit, branch, and merge operations. It is an official Hermes Agent memory provider with five-tier retrieval, four tiers of which are non-LLM, and includes a React/Ink TUI and REPL.

mnemosyne-oss / mnemosyne

Mnemosyne is a memory system for Hermes Agents that stores and recalls memories in SQLite. It supports MCP clients and direct Python use, and includes CLI commands for memory operations and sync.

moorcheh-ai / memanto

Memanto extracts and consolidates memories across agents, reconciles conflicting information, and manages forgetting. It also supports memory exchange through the Open Knowledge Format.

MemTensor / memmy-agent

Memmy Agent is a personal AI agent and local memory hub that provides a shared, controlled memory and persistent context across Claude Code, Codex, OpenClaw, and Hermes Agent. It offers a local Memory Service, a memory CLI, a desktop app, and an interactive TUI.

ClaudioDrews / memory-os

Memory OS is a seven-layer memory system for Hermes Agent that includes vector search, structured facts, fabric recall, and an auto-curated wiki. It uses local infrastructure including Docker, Qdrant, Redis, and SQLite, and its Ground Truth hierarchy is designed to ensure the agent prioritizes injected context.

greyhaven-ai / autocontext

Autocontext starts runs from a plain-language goal or saved scenario, then lets you inspect, diff, replay, or export filesystem-based run artifacts. Its support for multiple agent entry points, including Pi and MCP clients, makes it a fit for teams working across different agent interfaces.

vshulcz / deja-vu

Deja-vu searches session histories from supported coding agents so you can recall past decisions and work across agents, including from months-old sessions. It can also sync indexed histories between machines over SSH.

stephenschoettler / hermes-lcm

Hermes LCM is a Hermes Agent plugin that persists messages in a SQLite store organized as a hierarchical DAG. Its lcm_grep and lcm_recall tools support searching and recovering details from that history.

elkimek / honcho-self-hosted

Honcho Self-Hosted provides Hermes Agent with private memory that persists across sessions. It supports OpenAI-compatible providers and local inference servers, and includes an automated setup script for Docker, PostgreSQL, and Redis.

Signet-AI / signetai

Signet provides a local-first identity, memory, and secrets layer that connects to agent harnesses through hooks, plugins, or extensions. It can run on a local machine or as a team server, with a dashboard for browsing memory and asking questions.

plur-ai / plur

Plur stores shared agent memories as plain YAML files in an open engram format. It offers local search with keyword search as a fallback, plus CLI setup and an MCP server.

yoloshii / ClawMem

ClawMem is an on-device memory and context engine that combines BM25, vector search, rank fusion, and cross-encoder reranking. It can generate session handoffs and capture decisions and preferences, with integrations through hooks, MCP, and native agent plugins.

Sibyl-Labs / Sibyl-Memory

Sibyl-Memory stores long-term agent memory locally in a SQLite file, with FTS5 search and a five-tier schema. Its package family includes an SDK, CLI, Hermes adapter, MCP server, and LangGraph BaseStore.

EfficientContext / ContextPilot

ContextPilot reorders text and multimodal context for prefix-cache sharing, and provides a context index for reordering, deduplication, and cache-aware scheduling. It integrates with Hermes Agent as well as vLLM, SGLang, llama.cpp, and OpenClaw.

yantrikos / yantrikdb-hermes-plugin

YantrikDB is a self-maintaining Hermes memory plugin whose recall results include a why_retrieved reason. It uses an embedded backend by default, with an HTTP backend also available, and includes contradiction tracking and memory canonicalization.

JanYork / llm-wiki-cli

llm-wiki-cli is an agent-driven CLI for maintaining persistent, source-grounded knowledge across sessions. It builds a Wiki with citations and history without requiring embeddings or a vector database.

ccf / agentcairn

AgentCairn keeps durable, cross-project memory in inspectable Markdown files with frontmatter metadata, using an Obsidian vault as the source of truth. A local DuckDB cache supports hybrid search and retrieval, and coding-agent integrations are available through MCP servers and host-specific plugins.

amanning3390 / flowstate-qmd

Flowstate-qmd watches agent session logs to anticipatorily prefetch context, combining RAG and vector search with local-first storage using SQLite-vec and GGUF models via node-llama-cpp. Its MCP-native server can automatically configure major coding-agent clients.

yepyhun / Brainstack

Brainstack brings Hindsight, Graphiti, and MemPalace under a single memory owner, using SQLite, Kuzu, and Chroma for state and retrieval management. It gives the agent a purpose-built evidence packet for each query.

generalbusiness-ai / keep

Keep builds reflective memory with semantic search, BM25 full-text search, and ranked graph traversal. It can index codebases, URLs, and multimedia with OCR support, while edge tags link stored notes bidirectionally.

aliasocracy / hermes-tool-slimmer

Hermes Tool Slimmer reduces tool-schema token use through local keyword-based ranking and Tool Search support. It integrates through middleware without patching Hermes core on version 0.19 or later, and includes a dashboard for tracking savings and managing tool configurations.

conorbronsdon / agent-context-os

Agent Context OS is a Git-backed context and workflow layer for Claude Code, Codex, and other listed compatible coding agents. It includes workflows for migrations, handoffs, and memory proposals; integrations are opt-in rather than enabled automatically.

Ladybug-Memory / hermes-memory-plugin

This local-only Hermes memory plugin stores data in a single .lbdb embedded graph database file and uses importance-weighted recall to surface high-priority memories during context prefetch. Retrieval supports BM25 keyword search and named graph relationships between entries.

stepanov1975 / hermes-local-knowledge

Hermes Local Knowledge indexes configured local sources and selected Hermes runtime sources, then registers five tools for search, retrieval, traversal, feedback, and usage reports. It also registers pre_llm_call, on_session_end, and on_session_finalize hooks.

MukundaKatta / hermes-agentmemory

Hermes AgentMemory is a pull-model episodic memory plugin with an on-demand summarizer and a trace.jsonl audit log of prefetch operations. It supports immediate event deletion, so deleted events are not retained as persistent summaries.

hermes-labs-ai / hermes-blind

Hermes Blind recovers the original goal of a long Claude Code or Codex session from its first user turn, with goals, first-sentence, and full extraction modes. It skips tool output and other non-user-turn records, and does not use a summarizing model or external service.

piprail / piprail

Piprail provides a TypeScript SDK for x402 payments and an MCP server for budget-bound agent wallets. It operates without a backend, database, or API keys.

yonro / hermes-xmemo-plugin

The Hermes XMemo plugin runs inside Hermes and communicates with XMemo over HTTPS for durable cross-session memory with semantic search. It provides ranked, bounded context recall before a turn and includes a local SQLite reliability layer.

futurebrowser / hermes-exabase-plugin

The Hermes Exabase plugin integrates Exabase M-1 for self-organizing long-term agent memory. It provides tools to search and manually store memories, with configurable query expansion and result reranking for retrieval.

sourcevault-ai / sourcevault-code-tools

This Hermes Agent plugin provides private, local code memory for repositories, with slash commands for search, file reads, context, and grounded Q&A. It also supports repo syncing and indexed Git-history search, and works with Hermes CLI, Telegram, and Hermes Desktop.

visorcraft / MongrelDB-Hermes

MongrelDB-Hermes provides long-term memory for Hermes Agent, with AES-256-GCM encryption at rest enabled by default. It offers HNSW, sparse, and FM-index retrieval, and can run through native Rust FFI or an HTTP daemon.

penfieldlabs / hermes-penfield

Penfield provides Hermes Agent with 17 tools for memory management and knowledge graph traversal. Its hybrid search combines BM25, vector, and graph methods, and it can automatically checkpoint context during message compression.

conorbronsdon / agent-memory-kit

Agent Memory Kit is a file-based memory curation loop that uses Markdown files and produces JSON diffs for review, without a database. Its rot and lint curators flag stale or conflicting facts, while a local Git repository tracks and can revert changes.
