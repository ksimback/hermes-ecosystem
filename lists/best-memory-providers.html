Best Memory Providers for Hermes Agent

The top community-built memory and context management tools for Hermes Agent, ranked by GitHub stars. Memory is what makes Hermes self-improving — these tools extend its built-in recall with long-term semantic memory, graph-based retrieval, and cross-session persistence.

For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

Mem0 provides a universal memory layer for AI agents, with separate memory states for users, sessions, and agents, plus temporal reasoning and multi-signal retrieval. As an official Hermes Agent memory provider, it is available as an OSS SDK, a self-hosted server, or managed cloud.

vectorize-io / hindsight

Hindsight structures agent memory around retain, recall, and reflect operations for long-term memory workflows. It offers Python, Node.js/TypeScript, and Go clients, and supports multiple LLM providers, including local options.

volcengine / OpenViking

OpenViking organizes an agent’s knowledge, memories, and skills in one filesystem, with L0 abstracts, L1 overviews, and L2 details that can be loaded at different levels. It is an official Hermes Agent memory provider using viking:// URIs, and sessions can be archived with memories extracted as Markdown.

topoteretes / cognee

Cognee builds connected memory from documents, code, and conversations for agents that need persistent memory across sessions. It includes a CLI for remembering and recalling text and supports local text processing without an LLM.

supermemoryai / supermemory

Supermemory extracts facts from conversations and handles contradictions through a single API for memory, RAG, and connectors. It is an official Hermes Agent memory provider and also offers plugins for Claude Code, Cursor, Codex, and other tools.

garrytan / gbrain

gbrain is an opinionated brain for OpenClaw and Hermes Agent that stores sourced facts and supports corrections and withdrawal. It can connect to existing agents and share memory across them, with optional semantic search, synthesis, and background enrichment.

plastic-labs / honcho

Honcho stores messages and events on sessions, then reasons in the background to update peer representations for stateful agents. It is the upstream library used by the elkimek/honcho-self-hosted Hermes wrapper and is available as a managed service, local CLI, or self-hosted FastAPI server.

campfirein / byterover-cli

ByteRover treats memory as a Git-like context tree, with commit, branch, and merge operations over plain Markdown. It is an official Hermes Agent memory provider, offering five-tier retrieval and an interactive TUI and REPL.

mnemosyne-oss / mnemosyne

Mnemosyne is a SQLite-backed memory layer for Hermes agents, with one pure-Python dependency. It integrates through MCP, native providers, or a Python SDK; BEAM results are reported for v3.0.0, while LongMemEval is pending.

moorcheh-ai / memanto

Memanto consolidates memories, reconciles conflicting information, and briefs agents with relevant memories before they act. It also supports importing and exporting memory through the Open Knowledge Format.

MemTensor / memmy-agent

Memmy provides a local memory service and CLI for sharing persistent context across agents including Claude Code, Codex, OpenClaw, and Hermes Agent. It also supports desktop and TUI use.

ClaudioDrews / memory-os

memory-os combines vector search and structured facts in a seven-layer memory system for Hermes Agent, with an auto-curated wiki and fabric recall. Its Ground Truth hierarchy is designed to ensure the agent prioritizes injected context.

greyhaven-ai / autocontext

AutoContext runs agent tasks against evaluations, keeps useful lessons, and discards dead ends to support work on complex tasks. It leaves traces, reports, and playbooks as records of that process.

stephenschoettler / hermes-lcm

This Hermes Agent plugin uses a SQLite store and hierarchical DAG to persist messages. Its lcm_grep and lcm_recall tools help recover details from prior context.

vshulcz / deja-vu

Deja-vu searches session histories from 41 agents, including months of past sessions. It can surface recall at session start or after command failures, and sync sessions between machines over SSH.

elkimek / honcho-self-hosted

This self-hosted Honcho backend enables private, cross-session memory for Hermes Agent. It supports OpenAI-compatible LLM providers and local inference servers, with an automated setup script for Docker, PostgreSQL, and Redis.

Signet-AI / signetai

SignetAI is a local-first layer for agent identity, memory, and secrets that supports multiple agent harnesses. It can import files, webpages, and agent conversations, and includes a dashboard for browsing memories and their sources.

plur-ai / plur

Plur stores shared agent memory as plain-text YAML engrams on disk and offers local search after a one-time model download, with keyword fallback. Its README reports 95.6% R@5 on LongMemEval-S (N=500).

yoloshii / ClawMem

ClawMem is an on-device memory and context engine that combines BM25 and vector search with rank fusion and cross-encoder reranking. It can generate session handoffs and capture decisions and preferences, with integrations through hooks, MCP, and native agent plugins.

Sibyl-Labs / Sibyl-Memory

Sibyl-Memory is a file-based long-term memory plugin family with an SQLite-backed, five-tier schema and FTS5 search. It avoids vector databases and embedding models, and includes an SDK, CLI, MCP server, Hermes adapter, and LangGraph BaseStore.

EfficientContext / ContextPilot

ContextPilot optimizes context ordering for prefix-cache sharing, including for text and multimodal contexts. Its context index supports reordering, deduplication, and cache-aware scheduling, and it integrates with Hermes Agent as well as vLLM, SGLang, llama.cpp, and OpenClaw.

yantrikos / yantrikdb-hermes-plugin

This Hermes memory plugin uses an in-process backend by default, so no separate server is required. Its retrieval results include a why_retrieved reason, and the plugin supports canonicalization and contradiction tracking.

JanYork / llm-wiki-cli

This agent-driven CLI maintains source-grounded Wiki knowledge with citations and history across sessions. It is designed to help agents proactively recall and evolve persistent memory without embeddings or a vector database.

ccf / agentcairn

AgentCairn keeps durable memory in inspectable Markdown files with frontmatter, using an Obsidian vault as the source of truth. A local DuckDB cache supports hybrid search and retrieval, while MCP servers and host-specific plugins connect it to coding agents.

amanning3390 / flowstate-qmd

Flowstate-QMD watches agent session logs to prefetch context into an anticipatory cache, combining RAG and vector search. It is a local-first option with SQLite-vec storage, GGUF models via node-llama-cpp, and an MCP-native server with automated configuration for major coding agent clients.

yepyhun / Brainstack

Brainstack brings Hindsight, Graphiti, and MemPalace together under a single memory owner, using SQLite, Kuzu, and Chroma for state and retrieval. It distinguishes itself by preparing a purpose-built evidence packet for the agent on each query.

generalbusiness-ai / keep

Keep builds reflective memory with semantic search, BM25 full-text search, and ranked graph traversal. It can index codebases, URLs, and multimedia with OCR support, while edge tags link stored notes through navigable, bidirectional relationships.

aliasocracy / hermes-tool-slimmer

Hermes Tool Slimmer reduces tool-schema token use through local keyword-based ranking and Tool Search support. It integrates as middleware without patching Hermes core on version 0.19 or later, and includes a dashboard for monitoring savings and managing tool configurations.

conorbronsdon / agent-context-os

Agent Context OS provides Git-backed context and workflows in plain Markdown, with first-class adapters for multiple coding agents. Its reviewed handoffs use hash-checked proposals and receipts, making it a workflow-oriented option in this memory-provider list.

Ladybug-Memory / hermes-memory-plugin

This local-only Hermes memory plugin stores data in a single .lbdb embedded graph database file and supports BM25 keyword search and named graph relationships. Its importance-weighted recall is designed to surface higher-priority memories during context prefetch.

stepanov1975 / hermes-local-knowledge

Hermes Local Knowledge indexes configured local sources and selected Hermes runtime sources for capability search and routing. It registers five tools for search, retrieval, traversal, feedback, and usage reports, along with pre-LLM-call and session-end hooks.

MukundaKatta / hermes-agentmemory

Hermes AgentMemory is a pull-model episodic memory plugin with an on-demand summarizer and a trace.jsonl audit log of prefetch operations. It supports immediate event deletion, rather than retaining persistent summaries after deletion.

hermes-labs-ai / hermes-blind

Hermes Blind extracts a session’s original goal from its first user turn, offering goals, first-sentence, and full extraction modes. It skips tool output and other non-user-turn records, and does not use a summarizing model or external service.

piprail / piprail

Piprail provides a TypeScript SDK and MCP server for x402 payments, including budget-bound agent wallets. It is designed to operate without a backend, database, or API keys.

yonro / hermes-xmemo-plugin

The XMemo plugin provides durable cross-session memory with semantic search, using lifecycle hooks for pre-turn recall and session-end snapshots. It adds a local SQLite cache and write outbox, and can read memories from other connected agents for cross-agent continuity.

futurebrowser / hermes-exabase-plugin

The Exabase plugin integrates Exabase M-1 for self-organizing long-term agent memory and provides tools to search for or manually store memories. Retrieval can be configured to use query expansion and result reranking.

sourcevault-ai / sourcevault-code-tools

This Hermes Agent plugin provides slash commands for searching code, reading files, supplying context, and asking grounded questions about a repository. It also supports repo sync and indexed git-history search, and can be used with Hermes CLI, Telegram, and Hermes Desktop.

visorcraft / MongrelDB-Hermes

MongrelDB-Hermes provides long-term memory for Hermes Agent, with AES-256-GCM encryption at rest by default and native Rust FFI or HTTP daemon execution modes. Its retrieval options include HNSW approximate nearest-neighbor search, sparse retrieval, and FM-index retrieval.

penfieldlabs / hermes-penfield

Penfield provides 17 tools for memory management and knowledge-graph traversal, using hybrid search that combines BM25, vector, and graph methods. It also checkpoints context automatically during message compression.

conorbronsdon / agent-memory-kit

Agent Memory Kit is a file-based memory-curation loop that works with plain Markdown files and produces JSON diffs for review, without a database. Its rot and lint curators flag stale or conflicting facts, while a local Git repository tracks and can revert memory changes.
