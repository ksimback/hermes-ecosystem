overview

hermes-plugins is a collection of plugins and workflow skills for Hermes Agent. The plugins cover goals and planning, delegation, safety, memory, observability, and integrations; skills provide guidance for software development and autonomous-agent workflows.

  • Plugins install individually and remain disabled until enabled.
  • Plugins use the configured model through Hermes’s ctx.llm.
  • The README lists six workflow skills.

Plugins and skills for Hermes Agent. Checked on Hermes v0.22.5: every plugin passes hermes plugins doctor --ci and hermes plugins validate, and the skills load on a fresh install running a local model.

Install

A plugin installs one folder at a time and stays off until enabled:

hermes plugins install 42-evey/hermes-plugins/evey-goals --enable

A running gateway keeps the plugin code it loaded at start. Run hermes gateway stop and the next session starts a fresh one (or hermes gateway restart when the gateway is installed as a service). hermes plugins list shows what is enabled.

Skills install the same way, by path:

hermes skills install 42-evey/hermes-plugins/skills/software-development/verify-before-done

Or use the whole folder from a clone:

git clone https://github.com/42-evey/hermes-plugins ~/src/hermes-plugins
hermes config set skills.external_dirs "[~/src/hermes-plugins/skills]"

Skills

Workflow skills that fill gaps in Hermes's bundled set. Each links the bundled skills it works with (systematic-debugging, test-driven-development, requesting-code-review, spike).

Skill Use it
verify-before-done Before claiming work is fixed, done, passing or deployed
plan-before-building Before a multi-step build: decide the design, write the plan, get one approval
review-feedback On receiving code review or PR comments, before changing anything
delegation-brief Writing a delegate_task brief, and checking what comes back
work-ledger Work that spans sessions and must survive compaction
safe-cleanup Before deleting, overwriting or killing anything, or a test run on real data

Plugins

Plugins that need a model call it through ctx.llm, so they run on whatever provider and model you have configured, local ones included. A plugin that talks to an outside service reads its address and keys from the environment variables in the last column; while they are unset its tools say which variable to set. Plugins that use the time of day read Hermes's own timezone setting (HERMES_TIMEZONE, UTC when unset).
