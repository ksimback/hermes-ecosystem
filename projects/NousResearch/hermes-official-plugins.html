Hermes Official Plugins ☤

The official plugins for Hermes Agent, built and maintained by Nous Research.
One repo, every first-party plugin, installed in one line from the Hermes plugin catalog.

What is Hermes Agent?

Hermes Agent is the self-improving AI agent from Nous Research. It writes skills from experience and keeps improving them as it works, remembers what matters across sessions, and runs where you are: the terminal, the Hermes Desktop app, Telegram, Discord, Slack, WhatsApp, Signal and more, all through one gateway. You can bring any model (Nous Portal, OpenRouter, Anthropic, OpenAI, your own endpoint) and run it on a laptop, a $5 VPS or serverless infrastructure.

curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

A lean core, with plugins at the edges

The Hermes core keeps the parts every user needs: the agent loop, memory, skills, the gateway, model routing and the tool runtime. Everything specific to one product, one vendor or one hobby belongs in a plugin, which you install when you want it and which ships on its own schedule.

That gives you:

  • Smaller, faster installs. You don't download a Spotify client to run a coding agent.
  • Fixes without waiting for a release. A plugin ships a fix as soon as it's reviewed. It doesn't wait for the next Hermes version.
  • A clear owner for each integration. Vendor plugins live with the vendors who build them, community plugins with their authors, and Nous's own plugins live here.

The plugin catalog

The Hermes plugin catalog is the reviewed index of everything you can install: model providers, memory providers, messaging platforms, Desktop extensions, voice, web and automation tools. It has hundreds of entries from Nous, vendors and the community. Each entry is pinned to a reviewed commit, so what you install is exactly what was reviewed, and an update moves you only when a new pin passes review.

hermes plugins search            # browse the catalog
hermes plugins info spotify      # what it does, what it needs, which commit
hermes plugins install spotify   # install at the reviewed pin
hermes plugins update spotify    # follow the catalog to the next reviewed pin

Hermes Desktop has the same catalog under Capabilities → Plugins.

Catalog entries come in two tiers:

Tier Who maintains it Where it lives
official Nous Research This repo, one directory per plugin
community Vendors and independent authors Their own repos, reviewed when they enter the catalog

The plugins

Home Assistant

hermes plugins install homeassistant

A gateway platform plus four tools. Hermes watches your Home Assistant event bus, reacts to the state changes you care about, controls devices over the REST API, and replies as Home Assistant notifications. Cron jobs can deliver straight to your phone with deliver=homeassistant.

ha_list_entities · ha_get_state · ha_list_services · ha_call_service

Spotify

hermes plugins install spotify

Seven tools over the Spotify Web API: playback, Spotify Connect devices, the queue, search, playlists, albums and your library, plus hermes spotify login for a loopback PKCE login with your own Spotify developer app. Playback control needs Premium.

spotify_playback · spotify_devices · spotify_queue · spotify_search · spotify_playlists · spotify_albums · spotify_library

Claude Subscription DirectSDK experimental

hermes plugins install claude-subscription-directsdk

A model provider that runs Hermes turns on your Claude Pro or Max subscription through the official Claude Code CLI, with no separate API key or per-token bill. Hermes keeps its own agent loop, tools, approvals and compaction; the plugin drives the logged-in claude binary as a request-scoped model client, and refuses cleanly with an install hint when Claude Code is missing.

Pick it in hermes model → Claude Subscription DirectSDK (Experimental)

Memory Wiki

hermes plugins install hermes-memory-wiki

A dashboard and Desktop tab that turns your local session history into browsable subject pages and daily logs, plus a read-only audit panel for MEMORY.md and USER.md.

Dashboard tab · reads local history, writes nothing

Blender

hermes plugins install blender

The official Blender Lab MCP server over stdio, pinned to upstream, with a Blender workflow skill, so Hermes can read and change your Blender scene. Needs Blender 5.1+ with its MCP add-on, Git and uv. Its tools run Python inside Blender, so use trusted workflows.

MCP server + skill · Windows, macOS, Linux

Snyk

hermes plugins install snyk

Scan code (SAST), dependencies, container images, IaC and SBOMs through Snyk's first-party MCP server, with the snyk-security-scan workflow skill. Needs Node.js/npm and a free Snyk account.

MCP server + skill · browser login via snyk_auth

TouchDesigner

hermes plugins install touchdesigner

Drive a live TouchDesigner session through 404.zero's free twozero MCP server, which runs inside TouchDesigner itself, with the touchdesigner-mcp workflow skill and 20+ reference files (operators, GLSL, audio-reactive, instancing) bundled.

MCP server + skill · TouchDesigner on macOS or Windows

Accent Picker desktop

hermes plugins install accent-picker

An OKLCH colour wheel in the Hermes Desktop status bar. Drag it and the whole theme retints live, so theme authors can try accents in place. The colour is scratch state and never persisted.

Desktop plugin · status bar + palette commands

Langfuse

hermes plugins install langfuse

Traces every Hermes turn to Langfuse: one span per turn, one generation per LLM call with usage and cost from Hermes' own pricing (cache and reasoning tokens included), one observation per tool call and subagent. Content capture is sanitized by default, with metadata-only and full modes.

Observability hooks · Langfuse Cloud or self-hosted

REA

hermes plugins install rea

Reverse engineer programs with REA's MCP server: native binaries, .NET assemblies, Electron and JavaScript apps, Android packages, firmware and browser activity, with REA's reverse-engineer-anything workflow skill. Static JavaScript and archive inspection work out of the box; native decompilation needs your own Ghidra, Hopper or IDA. Needs Node.js 22.19+.

MCP server + skill · about 170 tools, loaded on demand

X Chat

hermes plugins install xchat

Talk to Hermes in X's end-to-end encrypted DMs. Hermes runs as the X account you connect: chat with it in your own self-chat ("message yourself"), or give it a separate account and DM that. Messages are decrypted and encrypted locally with X's official Chat XDK, so X only routes ciphertext. Supports encrypted media, threaded replies, group chats with mention gating, and cron delivery. hermes xchat setup shows which account Hermes will run as and registers its keys. Needs an X developer app with chat API access.

Gateway platform xchat · end-to-end encrypted

Singularity/Apptainer

hermes plugins install singularity

A terminal backend that runs Hermes's terminal, file and code tools inside a hardened, rootless Apptainer or Singularity container on this machine, with CPU/memory limits and an optional persistent overlay. Built for HPC clusters and shared machines where Docker isn't available. Formerly built into Hermes core.

Terminal backend terminal.backend: singularity · Linux

Agent Importers

hermes plugins install agent-importers

hermes import-agent brings an OpenClaw, Claude Code, Codex CLI, Cursor, Grok Bot or OpenBot setup into Hermes in one command (Grok Bot and OpenBot routines become Hermes cron jobs): instructions, Cursor rules and memories become memory entries, Bash permission rules become allow/deny lists, MCP servers land in config.yaml and skills are copied. Always previews first and never imports API keys (OpenClaw's allowlisted secrets only with --migrate-secrets); --sync re-imports sources that changed. The old hermes claw migrate / hermes claw cleanup spelling and the openclaw-migration skill come along. Formerly built into Hermes core.

CLI command · hermes import-agent [openclaw|claude-code|codex|cursor|grok-bot|openbot]

MCP Serve

hermes plugins install mcp-serve

Run Hermes as an MCP server: hermes mcp-serve gives Claude Code, Claude Desktop, Cursor, Codex or any MCP client your messaging conversations across every connected platform, live new-message events and sending. --tools (off by default) adds Hermes' web, browser, vision, image generation, skills and TTS tools; terminal, file and kanban tools are never exposed. Formerly hermes mcp serve in core.

stdio MCP server · 10 conversation tools, +17 with --tools

Bubblewrap

hermes plugins install bubblewrap

A terminal backend that runs every terminal and execute_code command in its own bwrap sandbox on this machine, at the same paths: read-only root, writable working directory, SSH keys, cloud credentials and the Hermes home hidden, private /tmp and /proc, agent sockets masked, memory, CPU and process limits. No image, no daemon. The file tools (read_file, write_file, patch, search_files) run in the sandbox too.

Terminal backend terminal.backend: bubblewrap · Linux

Meshy

hermes plugins install meshy

Make 3D models with Meshy's first-party MCP server: text or image to 3D, texturing, rigging and animation, format conversion, and 3D-print preparation (printability repair, multicolor 3MF, split into parts, slicer handoff), with a meshy-3d workflow skill. Hermes asks before every credit-spending call. Needs Node.js 18+ and a Meshy API key (Pro plan).

MCP server + skill · 28 tools, loaded on demand

Advanced Delegation

hermes plugins install advanced-delegation

Two more ways for delegate_task to route subagents. Model routes: the agent picks a named model route per subagent (fast, deep, local...) from a list you write. Profile routes: it runs a subagent as one of your Hermes profiles, with that profile's model, skills and credentials. Only the names and your one-line descriptions reach the model.

hermes delegation config · /delegation to switch modes in a chat · Hermes 0.22.5+

Camofox

hermes plugins install camofox

Browse with Camofox, a self-hosted anti-detection Firefox (Camoufox) behind a local REST server: navigate, accessibility snapshots with clickable refs, click, type, scroll, keys, screenshots analysed by your vision model, read-only JavaScript, and cookie import. Optional persistent profiles keep logins across restarts. Your existing CAMOFOX_URL and browser.camofox settings carry over. Formerly built into Hermes core.

11 browser tools · toolset camofox · needs a running camofox-browser server

ElevenLabs Sound Effects

hermes plugins install elevenlabs-sound-effects

Sound effects on demand from ElevenLabs: describe a sound ("glass shattering on a tile floor", "90s hip-hop drum loop, 90 BPM") and Hermes generates it, up to 30 seconds and optionally a seamless loop, and sends you the audio file. Uses the same ELEVENLABS_API_KEY as Hermes's ElevenLabs voice; model, format and endpoint are plugin settings.

elevenlabs_sound_effect · billed to your ElevenLabs account

ElevenLabs Music

hermes plugins install elevenlabs-music

Songs and instrumentals from ElevenLabs Music: describe a track or paste your lyrics and Hermes writes, generates and sends it, 3 seconds to 10 minutes. It can redo one section, extend or loop a song, split it into vocal, drum and bass stems, and score a video. Long songs finish in the background and arrive in the chat. In Hermes Desktop each track gets a music card with synced lyrics and a library tab.

elevenlabs_music_compose and 7 more · billed to your ElevenLabs account

Security

hermes plugins install hermes-security

Security review for a local repository. Parallel subagents read the code in chunks, check each candidate against the code, and trace whether an attacker can reach it. Optional tests confirm findings in a temporary copy, and an optional grant lets the agent test your running app for an hour. Reports keep evidence, coverage gaps and rejected candidates, export to Markdown, JSON, CSV and SARIF, and get a Security page in Hermes Desktop.

security_scan_start and 8 more · /security · hermes security-review

More on the way

Official plugins move in here as they leave Hermes core or join from their own repos. Browse everything else, from Nous, vendors and the community, in the plugin catalog. Experimental plugins we built but don't support live in hermes-labs-plugins.

Already used one of these?

Most plugins here used to live somewhere else: Home Assistant and Spotify were built into Hermes core and then briefly had their own repos, Langfuse shipped bundled with core as observability/langfuse, the Singularity/Apptainer terminal backend and the Camofox browser backend were built into core, MCP Serve was core's hermes mcp serve, and the rest each had a standalone NousResearch/hermes-* repo. Except for MCP Serve, you don't need to do anything.

  • You used the built-in Home Assistant, Spotify, Langfuse, Singularity or Camofox backend: hermes update, or the first start after updating, installs the plugin from the catalog with your existing config, env vars and login.
  • You installed it from the catalog: the catalog now points here, so hermes plugins update <name> moves your install to this repo and keeps your files.
  • You used the built-in hermes import-agent: profiles that registered an import for --sync get the agent-importers plugin on update; anywhere else, running hermes import-agent prints the one-line install (hermes plugins install agent-importers).
  • You used hermes claw migrate (OpenClaw): it now comes with the same plugin. After hermes plugins install agent-importers, both hermes import-agent openclaw and the old hermes claw migrate / hermes claw cleanup work with the same flags.
  • You ran hermes mcp serve: install with hermes plugins install mcp-serve and change your MCP client's args from ["mcp", "serve"] to ["mcp-serve"]. MCP clients are configured outside Hermes, so this one is not installed for you.
  • You installed it by URL (for example hermes plugins install NousResearch/hermes-homeassistant): reinstall once from the catalog with hermes plugins install <name> --force to follow future updates. The old repos are archived and get no new fixes.

Repository layout

hermes-official-plugins/
├── assets/                         # README and catalog art
├── homeassistant/                  # one self-contained plugin per directory
│   ├── plugin.yaml                 #   manifest: name, tools, env vars, Hermes version
│   ├── __init__.py                 #   register(ctx)
│   ├── pyproject.toml              #   plugin dependencies
│   └── tests/                      #   the plugin's own suite
├── blender/                        # portable plugins: plugin.json + mcp.json + skills/
├── accent-picker/                  # Desktop plugins: plugin.yaml + desktop/plugin.js
└── ...

Each directory is a complete Hermes plugin. The catalog installs one by repo + subdir at a pinned commit, and Hermes fetches only that directory (a blobless sparse clone), so installing Spotify never downloads Home Assistant.

Development

Every plugin is tested against current Hermes core on Linux, macOS and Windows, on every push and pull request. A nightly run catches core changes that break a plugin before users see them.

git clone https://github.com/NousResearch/hermes-agent
git clone https://github.com/NousResearch/hermes-official-plugins
cd hermes-official-plugins/spotify
HERMES_AGENT_REPO=../../hermes-agent PYTHONPATH=../../hermes-agent python -m pytest -q

To try your local checkout in a real Hermes, install the directory: hermes plugins install ./spotify --force.

Releasing: merge to main, then open a PR on hermes-agent that bumps the plugin's sha: in plugin-catalog/<name>.yaml. The catalog pin is the release; every installed copy moves on its next hermes plugins update.

Issues: open them here and name the plugin in the title ([spotify] ...). Bugs in Hermes core belong on hermes-agent.

Build your own

Plugins are plain Python with a plugin.yaml. Start with the plugin guide and the example plugins, then submit yours to the catalog.
