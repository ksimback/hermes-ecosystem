overview

FlipsiBridge connects an Android device to a Hermes server so an AI agent can use device actions such as camera, screen, files, and notifications. It uses an encrypted chat and a self-hosted relay; the phone connects to the relay over WebSocket and can work behind NAT without port forwarding.

FlipsiBridge

Remote Android device control for AI agents. Self-hosted, MIT-licensed: give your AI agent hands on your phone — voice, camera, screen, files, notifications, health and 40+ device actions. Chat and media are end-to-end encrypted with a Double Ratchet (the relay sees only ciphertext); device commands travel over your own TLS-authenticated relay. Built for the Hermes Agent ecosystem.

Screenshots

  

Features

  • End-to-end encrypted chat - Double Ratchet (X25519 + X3DH + AES-256-GCM) phone <-> agent; the relay sees only ciphertext
  • Multi-agent chat - multiple agents in one app: status chips (sent/delivered/read), presence, offline spool (24 h)
  • 40+ device tools - camera, screen, screen recording, files, notifications, microphone streaming, media, clipboard, SMS, calls, apps
  • Health Connect integration - read-only aggregates (steps, heart rate, sleep), default OFF per capability
  • OEM compatibility profiles - Xiaomi/HyperOS, Samsung/One UI, OPPO/realme/OnePlus, VIVO/iQOO, Huawei/Honor, Motorola, Nothing + generic AOSP fallback
  • Two editions, one codebase - GitHub edition (full features) and Play edition (Google-compliant, per flavor)
  • Capability gating - every device permission is an explicit opt-in switch, default denied
  • Connects out, works behind NAT - no port forwarding, no VPN; the phone opens the WebSocket to your own server

How it works

Phone (home WiFi)  ──WebSocket──>  Hermes Server (cloud)  <──HTTP──  AI Agent
                                   relay on port 8766

The phone connects out to your Hermes server — works behind any NAT, no port forwarding, no VPN, no USB. Just a 6-character pairing code.

Backend installieren (Server) — Einzeiler

curl -fsSL https://raw.githubusercontent.com/TechFlipsi/FlipsiBridge/main/install-relay.sh | ANDROID_BRIDGE_TOKEN=<CODE> bash

Der Code steht in der App (Setup-Screen). Danach die Handy-App verbinden (URL http://dein-server:8766 oder https://deine-domain.tld via Reverse-Proxy + TLS).

Quick Start

1. Install the bridge app on your phone

Option A — Download the prebuilt APK (easiest). Every push to main automatically publishes a fresh debug APK to the Latest Build release. Download the flipsibridge-<version>-github.apk asset from there and install it — either by opening the file on the device (enable "Install unknown apps" for your browser/file manager when prompted) or via adb install flipsibridge-*-github.apk.

Option B — Build from source:

cd hermes-android-bridge
./gradlew assembleGithubDebug
adb install app/build/outputs/apk/github/debug/flipsibridge-*-github.apk

The APK is an unsigned debug build, which is why Android/Play Protect may warn on install — it is not yet published on the Play Store or F-Droid.

2. Grant permissions on the phone

  • Open Hermes Bridge app
  • Tap Enable Accessibility Service → find Hermes Bridge → toggle ON
  • Tap Enable Status Overlay → grant permission
  • Tap Grant Screen Recording → approve the system dialog (needed for android_screen_record)
  • Grant additional runtime permissions in Settings > Apps > Hermes Bridge > Permissions:
    • Microphone — for android_mic_record
    • Location — for android_location
    • Contacts — for android_search_contacts
    • SMS — for android_send_sms
    • Phone — for android_call (direct dialing)
  • Enable Notification Listener in Settings > Apps > Special app access > Notification access → enable Hermes Bridge (for android_notifications / android_events)

3. Connect to your Hermes server

Tell hermes (via Telegram, Discord, etc):

Connect to my phone, code is <CODE>

Where <CODE> is the 6-character pairing code shown in the app.

Hermes will reply with the server address. Enter it in the app and tap Connect.

Full install detail (permission → tool mapping, AAOS, persistent systemd relay) lives in docs/install.md.

4. Done

The agent can now control your phone. Try: "open Instagram", "take a screenshot", "what apps do I have?"

Android Automotive OS (Car Head Units)

The bridge app can run on Android Automotive OS (AAOS) car head units. Phone-specific features (SMS, calls, contacts) gracefully return errors when the hardware is unavailable.

Installation

  1. Get the APK: download flipsibridge-<version>-github.apk from the Latest Build release, or build it with cd hermes-android-bridge && ./gradlew assembleGithubDebug
  2. Sideload via ADB: adb install flipsibridge-*-github.apk
    • USB: connect directly to the head unit's USB port
    • WiFi: adb connect <head-unit-ip>:5555 then install
  3. Grant Accessibility Service: Settings > Accessibility > Hermes Bridge > Enable
  4. Grant overlay permission: Settings > Apps > Special access > Draw over apps > Hermes Bridge
  5. Skip phone-specific permissions (SMS, calls, contacts) — not applicable

Connection

The car head unit needs network access to reach the relay server:

  • USB tethering (recommended): adb forward tcp:8766 tcp:8766, then enter http://localhost:8766 in the app
  • WiFi: enter the relay server's http://<ip>:8766 in the app (both devices on same network)

Architecture

Android app (Kotlin):

  • AccessibilityService reads the UI tree and performs taps/types/swipes
  • WebSocket client (OkHttp) connects out to the Hermes server
  • Ktor HTTP server for local/USB development
  • Pairing code authentication
  • Screenshot capture via AccessibilityService API
  • Terminal-themed UI

Server (Python):

  • WebSocket + HTTP relay (aiohttp) on port 8766
  • Tools register into hermes-agent's tool registry
  • Rate-limited authentication (5 attempts / 60s, then 5min block)
  • Auto-detects server public IP for setup instructions

Security

See SECURITY.md for details. Key points:

  • Pairing code authentication with rate limiting
  • Phone connects out (never directly exposed)
  • Transport encryption: native TLS (ANDROID_RELAY_TLS=1 + cert/key, wss://) or via TLS reverse proxy — the relay refuses plaintext binds off-localhost by default
  • Full device access once paired — only connect to trusted servers

Roadmap

This is a working prototype. The vision: give Hermes its own phone — a fully autonomous mobile presence.

Shipped milestones live in the CHANGELOG — notifications, clipboard, direct SMS/calls, location, microphone recording, screen-wake key, text-to-speech, and a persistent systemd relay are all in. What's still ahead:

Upcoming

  • Certificate pinning in the app (with backup pins for CA rotation)
  • Server-side call counter to prevent tool call loops
  • Better error reporting (screenshot + annotated explanation on failure)
  • File transfer — send files/photos between phone and server
  • Multiple phones — connect more than one device to the same relay
  • Scheduled automations — "every morning, check my commute price on Bolt"
  • Event triggers — "when a notification arrives from this app, do X"
  • Macro recording — watch a workflow once, replay it on demand
  • Phone call capability — answer and speak in calls using TTS/STT
  • Voice assistant mode — always-listening on the phone, responds via speaker
  • Call handling — answer, take a message, relay a callback
  • Local model execution — run small models (Qwen 0.5B, Gemma 2B) on-device
  • Offline fallback — basic commands work without server using an on-device model
  • Hybrid routing — simple tasks locally, complex tasks to the server
  • On-device app adapters — fast structured parsing without server round-trips
  • iOS support via Shortcuts/accessibility bridge
  • Web dashboard for monitoring phone activity
  • Cross-app workflows — "find a restaurant on Maps, share on WhatsApp, book an Uber there"
  • Agent-framework adapters — OpenClaw & co. (community adapters onto the framework-agnostic wire protocol)
  • Dedicated "Hermes Phone" — a phone that boots straight into agent mode

Other agent frameworks (OpenClaw & co.)

FlipsiBridge's agent-facing side is deliberately thin: the wire protocol between your phone and the relay is agent-framework-agnostic — the E2E-encrypted channel (Double Ratchet) terminates at your relay, and only a small adapter layer connects that relay to your agent runtime's tool system. Today a first-class adapter ships for Hermes Agent (Python toolset + plugin, above). The same pattern is architecturally portable to other runtimes — e.g. OpenClaw's plugin/skill system (Node/TypeScript) could speak the relay protocol (WebSocket + JSON, Web Crypto for the ratchet) and expose the 40+ device tools as native OpenClaw tools.

No OpenClaw adapter ships yet — so FlipsiBridge currently runs on Hermes only. If you're building one, we want to hear from you: open an issue in this repo and we'll help with protocol details and cross-language crypto vectors (reference implementations exist in Kotlin and Python and are pinned by tests on both sides).
