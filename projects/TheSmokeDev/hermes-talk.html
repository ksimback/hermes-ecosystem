Hermes Talk is a plugin that adds interruptible, two-way voice conversations to Hermes Agent. It can run in the terminal, Discord voice channels, the Hermes dashboard, and Hermes Desktop, while using the agent’s tools and handing longer jobs to background agents.

Hermes Talk

Realtime voice for Hermes Agent. Press Talk, say what you need, and cut in whenever you like. Your agent keeps using its real tools while you talk.

Hermes Talk is a plugin for Hermes Agent that turns it into something you can talk to. You speak, it answers out loud, and you can interrupt it mid-sentence. While you talk it calls the agent's own tools, hands longer jobs to background agents, and tells you how they went when they finish.

It runs in the terminal (hermes talk), in a Discord voice channel (/talk join), in the Hermes dashboard Talk tab, and in Hermes Desktop.

No extra API bill on the main lanes. OpenAI Realtime runs on the ChatGPT subscription you already have (sign in once with codex login), and Grok Voice runs on your X Premium or SuperGrok login. Gemini Live uses a free AI Studio key (GEMINI_API_KEY). The local lane runs on your own model server with no key at all. Prefer API keys? Those work too.

Hermes Talk adds duplex voice to a Hermes install you already run. It is not a standalone assistant, and it doesn't replace Hermes's built-in turn-based voice mode, which is a different (and good) design.

Watch the 0.24 film (1:40, with sound): the one-button panel, switching coding chats by voice, Phone mode, Discord, Echo and the community behind it. Narration and sample conversations are for demonstration; the features are real.

The original dashboard demo is a real Realtime session recorded at v0.3.0.

New in 0.24.0

A big community release. The community features in the new Experimental section ship switched off, so the Talk button you know works exactly as before.

  • One-button Talk. Desktop and the dashboard Talk tab now open on one large voice button with a short status line. Pressing it starts Talk in one step, exactly as before. Mute and Sleep show up beside it while you're connected. Typing, recipients and attachments sit under Type a message, and voice and conversation choices live under Settings.
  • Experimental settings. A new Experimental section in the Hermes Talk plugin settings holds a saved Amazon Echo, a text-only call journal, voice language and a speaker echo hold for speakers with output lag, like a TV over HDMI. Echo and the journal start off, language starts on Auto, and the echo hold starts at 0. Details: Experimental plugin settings.
  • Switch chats by voice. On a compatible Hermes host you can say "Switch to my Codex chat and read its last reply", then "Ask it to check mobile too." It works with Claude Code chats as well. If several chats match, Talk asks which one you mean. Host requirements and the full phrase list are in recipient-routing.md.
  • Twilio phone server (experimental). python -m talk_twilio_server answers calls to your own Twilio number with a fresh Gemini Live session that has no task and no tools. Webhooks are signature-checked, callers must be on an allowlist, and normal Talk never loads it. It hasn't been confirmed on a real call yet. See TWILIO.md.
  • Profile isolation. On a multiplexed gateway, Talk settings and keys come from the profile serving the turn, Discord voice uses that profile's own bot, and background work keeps the profile that started it.
  • Discord playback and honest outcomes. Replies stop cleanly at their boundaries and queued announcements resume after playback drains. A run that failed, was stopped or was interrupted is now announced as exactly that. Delegated work also stops filling the call with empty "still working" lines.
  • Fixes people asked for. The end-of-call transcript review no longer re-spawns itself. Gemini Live no longer fails to start with close code 1007 on tool schemas. hermes talk doctor no longer crashes on a host with no audio system.
  • One sign-in for the dashboard. When the dashboard's own sign-in is on, that sign-in opens the Talk tab, with nothing to paste per browser tab. An explicit TALK_DASHBOARD_TOKEN still protects deployments that set one.

Still fresh from 0.23: an optional Phone mode powered by Dograh, and TALK_PROVIDER=local for running the voice lane on your own GPU (LOCAL.md). From 0.22: start, check and steer Desktop sessions by voice (DESKTOP.md).

Install

Use the pinned plugin install or upgrade command in the 0.25.0 release notes. For Python microphone and speaker support, run pip install "hermes-talk[audio]==0.25.0".

You need Python 3.11 or newer and a Hermes host at v0.23.0 or newer. GPT-Live, shared task attachment and Codex workers need extra host capabilities, listed in Prerequisites.

Restart the gateway, the dashboard and Desktop afterwards. A running process keeps the old code until you do. An unpinned Git install can use hermes plugins update hermes-talk.

Using Desktop? Installed agent packages are opt-in there. In Desktop Capabilities → Plugins, turn on the Desktop half of Hermes Talk if it is off. Installing the Python wheel alone doesn't register it; the plugin installer does. More in the Desktop guide.

Quickstart

Terminal. Start here:

hermes talk

Speak, and it answers out loud. Ctrl+C hangs up. More in Use.

Discord. The call happens in a voice channel, not in chat:

/voice join     # put Hermes in the voice channel first
/talk join      # Talk borrows that connection; it never opens a second one

Everyone in the room hears the answers, and /talk leave ends the call. Tools that change things stay denied until you set TALK_DISCORD_OPERATOR_USER_IDS. See Discord voice.

Dashboard. Browser audio, no local mic drivers:

hermes dashboard    # then open the Talk tab and press the voice button

Allow the microphone and talk. You get the live transcript and a list of background runs. See Dashboard tab.

Desktop. Open a conversation, click Talk in the top bar or beside the composer, then press Start talking. The popover closes once you're connected and the audio keeps running; Stop stays beside the composer. On stock Desktop, send one message first so the conversation exists. See DESKTOP.md.

Optional native Phone mode

Phone mode lets you continue a Hermes conversation over a phone call, with its existing history, memory and tools. It is part of Hermes Talk, powered by Dograh, and off by default. Normal Talk needs no Dograh account.

To set it up, enable it in Hermes's plugin settings, then connect a dedicated Dograh account and a caller number you already own:

hermes talk phone setup     # connect Dograh and your number
hermes talk phone doctor    # connection checks

Call tools, review controls, status and caller questions all run through the Hermes conversation you already have. /phone review CALL_ID opens the host's native approval picker, and /phone answer REQUEST_ID ANSWER sends an authenticated owner answer back into the call. Desktop, dashboard and mobile viewers use the host's message stream; Discord uses its existing adapter and channel or thread. There is no separate Phone dashboard.

Some ground rules:

  • Installation never dials or buys a number.
  • Dograh and its configured carrier, STT, LLM and TTS services can charge for carrier use, hosting and models. Audio, transcripts and recordings are handled according to that account's provider settings.
  • Keep keys in Hermes secret settings, allowlist exact owned numbers, and review every call.
  • Phone Stop prevents new calls and revokes grants. It does not hang up a call the carrier already has in progress.
  • The optional in-call bridge starts only with hermes talk phone bridge. Configure its private relay or HTTPS proxy before you accept remote caller questions.
  • An existing separate Dograh test setup can be imported with hermes talk phone setup --import-dograh. The original journal is kept and its old approvals are revoked.

The Twilio phone server is a different, standalone experiment and is not part of Phone mode.

Is it working?

hermes plugins list        # hermes-talk, enabled, current version
hermes talk doctor         # read-only: auth lane, provider, model/voice, audio, host lanes
hermes talk check          # doctor plus one live provider turn and one bounded Hermes run

Then, in any session, say "status report". talk_status answers with the version, auth lane, agent lane and audio state.

doctor only reads. It names the lane that came up and what is missing, and it never writes, probes or refreshes a token. check is deliberately not read-only: it runs one short provider turn and one short agent run, and exits 0 only if every step passed. A mock can't turn it green.

Filing an issue? hermes talk diagnostics --bundle writes one redacted, owner-only file with versions, the names of the variables you've set, device and host facts, and every doctor outcome. It holds no values, logs, prompts, transcripts, audio or paths, so it is safe to paste into a public issue, and it is what the bug template asks for.

Design rules

Three rules shaped everything else.

  • Nothing fails quietly. A degraded backend, a missing tool or a run whose watcher died gets said out loud in the conversation. A voice surface that quietly does less than you asked is worse than one that refuses.
  • The credential never leaves the process. The key or OAuth token reaches exactly one OpenAI endpoint (the mint), and the socket only ever sees the short-lived secret that endpoint returns.
  • Hermes owns the tools and the session. The Realtime layer handles ears, mouth and turn-taking. It never owns the agent loop.

Background

Hermes Talk started as a plugin and became a reference implementation for a proposed speech-to-speech contract in Hermes core:

  • RFC NousResearch/hermes-agent#77111, filed from this repo, proposes a RealtimeVoiceProvider ABC for Hermes core.
  • PR NousResearch/hermes-agent#101808 carried the proposed core contract, orchestrator and first built-in provider, ported from this plugin. It was closed without merging, so no Hermes release has the contract today. Hermes Talk detects it and publishes its three lanes only on a host that has it (details).
  • PR NousResearch/hermes-agent#97325 adds a pointer to this plugin on the official Voice Mode docs page.

Open epics: #19 provider-neutral Realtime voice platform, #32 operator-grade orchestration UX, #43 Talk over the Bot Mode roster, and #44 channel-neutral voice transport.

Come build with us

New features land behind Experimental settings, off by default, so you can ship something ambitious without changing anyone's Talk button. Getting started takes seconds and needs no keys:

pip install -e ".[dev]" -r requirements-lint.txt
pytest -q
ruff check .

CONTRIBUTING.md covers priorities, where each kind of change starts (a provider, a surface, a tool, a fix), the merge bar, and the one test trap on a machine that has Hermes installed. You'll get a first response within 24 hours, and merged work is credited by name in the CHANGELOG and here. A good first issue fits in one sitting, and a provider receipt for a lane that worked or broke for you counts too. Ideas and questions go to Discussions.
