Hermes Remote Browser

Your agent lives on a server. Your logged-in browser doesn't.

Let a Hermes Agent on a home server or VPS use Chrome on your own computer, across networks, with the sessions you're already logged into. Your computer needs only a browser extension: no companion app, VPN client or inbound ports.

See it in action

Download the MP4: a server-hosted Hermes agent uses Chrome on a separate laptop to find an existing GitHub issue, avoid creating a duplicate, and reopen it when asked. Playback is accelerated, pauses are cut, and audio is removed. Browser toolbar and desktop status details are covered. The recording uses the original Penny Bridge branding; this repo packages the bridge as Hermes Remote Browser.

  • Share tabs by moving them into the purple Hermes group. Other tabs stay out of reach.
  • Switch access on yourself. It automatically switches off after your chosen interval and at browser start.
  • Keep using your own browser sessions. You don't need to copy cookies to the server.

The server needs a public HTTPS hostname with websocket support. The extension currently installs through Chrome's Load unpacked flow. Page text and screenshots enter your Hermes conversation and may reach your model provider; read the security model before sharing sensitive tabs.

Try it and tell us what breaks

We're looking for the first five community testers running Hermes on a server and Chrome on a separate computer. Follow the first-run checklist, then report your result. A failed setup report is useful too. Please leave out tokens, private page contents and pairing codes.

Quick start

1. Install the plugin. Tell your Hermes agent:

Install the Hermes plugin https://github.com/driftverse/hermes-remote-browser and set it up.

Or run it yourself on the server:

hermes plugins install driftverse/hermes-remote-browser --enable

Then restart Hermes. If you use the web dashboard / Hermes Desktop, restart that too. The relay starts by itself. The plugin includes a setup skill, so the agent knows how to walk you through the rest.

2. Give the relay a public HTTPS address. Point a hostname at http://localhost:9178 on the server. With Cloudflare Tunnel, add a public hostname with service type HTTP, URL localhost:9178. Any HTTPS reverse proxy with websocket support works.

3. Add the extension to Chrome. Download hermes-remote-browser-extension-*.zip from the latest release, unzip it, open chrome://extensions, switch on Developer mode, click Load unpacked, and pick the unzipped hermes-remote-browser-extension folder. (The same files are in extension/ in this repo.)

4. Pair. Click the purple H icon, enter wss://your-hostname, and click Pair this browser. Tell your agent "approve the browser code ABC-123" (Hermes asks you to confirm). Click Switch on.

Done. Ask your agent to do something in your browser.

How it works

 Your computer                                 Your server
┌──────────────────────────┐                 ┌────────────────────────────────────────┐
│ Chrome                   │   wss (out)     │ reverse proxy / tunnel (HTTPS)         │
│  └ Hermes Remote Browser ├────────────────▶│  └ relay.py  127.0.0.1:9178  /ext      │
│     extension            │                 │       ▲ control.sock (owner-only)      │
│  └ purple "Hermes" tab   │                 │       │                                │
│    group = what the      │                 │  Hermes Agent ── remote_browser tool   │
│    agent can see         │                 │       (this plugin starts the relay)   │
└──────────────────────────┘                 └────────────────────────────────────────┘
  • The extension dials out. Your computer opens no ports and needs no VPN client or companion program.
  • The agent only sees the tabs you share. It can use tabs in a purple Hermes tab group, and the tabs it opens itself land there. Drag a tab into the group to share it. Everything else in your browser stays invisible.
  • Off by default. You switch it on from the toolbar icon. It switches itself off again after 15 min / 1 h / 4 h (your choice) and at every browser start.
  • Pairing without secrets. The extension shows a short code that you approve on the server. The browser then holds a random device token; the server stores only its hash.
  • Password fields are off-limits. The extension refuses to read or type into them.
  • Real mouse input. Version 1.1 adds Chrome's debugger permission for scoped mouse input. Chrome shows a debugging notice while attached; it detaches after each action. Tab-group restrictions are enforced in extension code, not by Chrome's broad permission scope.
  • The relay runs itself. The plugin starts relay.py in the background when Hermes loads it, using Hermes's own Python (it needs aiohttp, which Hermes already has). Only one relay runs per machine, and it keeps running across Hermes restarts. Paired browsers are kept in ~/.local/share/hermes-remote-browser, so reinstalling the plugin doesn't unpair them.

What the agent can do

One tool, remote_browser, with these actions:

Action What it does
setup First-time checklist: relay status, port, extension folder, pairing
status Is a browser connected?
tabs List the tabs in the Hermes group
focus Select an existing shared tab, expand its group and focus its window without navigating
open Open a URL (or reuse a shared tab); foreground: true brings it into view, default stays in background
snapshot Page title, URL, visible text and a numbered list of clickable/typeable elements
click / type / select Act on an element by its number from the latest snapshot
scroll up / down / top / bottom; optional ref targets an inner panel, reports whether it moved
mouse Real click / move / drag / wheel at viewport CSS coordinates, with a visible purple pointer
key Press a key (Enter, Escape, Tab…) on the focused element
back Go back
screenshot Capture the tab (brings it to the front of its window)
close Close a Hermes-group tab
pairing_requests / approve_pairing See and approve pairing codes (approval always asks you)

The bundled skill remote-browser:remote-browser tells the agent how to set things up and use the tool safely.

Requirements

  • Hermes Agent with plugin support (tested on v0.22.5 on Linux; macOS should work)
  • A public HTTPS hostname that forwards websockets to the relay's port
  • Chrome (or another Chromium browser) 116 or newer on your computer

Managing it

Optional command-line helper (works over the relay's control socket):

install -m 755 ~/.hermes/plugins/remote-browser/bin/remote-browser ~/.local/bin/
remote-browser status          # connection, pending codes, paired browsers
remote-browser approve CODE    # approve a pairing code
remote-browser revoke ID       # unpair a browser (it switches off right away)
remote-browser logs            # relay log

Update the plugin with hermes plugins update remote-browser. To pick up a new relay.py, stop the running relay (pkill -f remote-browser/relay.py); the next tool call starts the new one.

Configuration

Set these in the environment Hermes runs with (e.g. its service file):

Variable Default Meaning
REMOTE_BROWSER_PORT 9178 Port the relay listens on (loopback only)
REMOTE_BROWSER_HOST 127.0.0.1 Address the relay listens on
REMOTE_BROWSER_HOME ~/.local/share/hermes-remote-browser Paired browsers, control socket, log

Security model

Read this before using it with accounts that matter.

What runs on your server: one long-running background process, relay.py, started by the plugin. It listens on 127.0.0.1:9178 (only reachable through the HTTPS address you set up) and on an owner-only unix socket. It keeps its files in ~/.local/share/hermes-remote-browser: the paired browsers (token hashes only), the socket and a log. It makes no outbound network calls, runs no shell commands and stores no credentials. The extension talks only to the address you enter.

  • What the agent sees, its model provider sees. Page text and screenshots go into the conversation, and from there to whatever LLM provider your Hermes uses. Pick providers you trust.
  • The gate is on your side. The switch, auto-off and the tab group are enforced in the extension, so the server can't widen them. Browsing actions don't ask for approval each time; sharing a tab is the approval.
  • Pages can try to trick the agent. A malicious page can contain instructions aimed at the agent (prompt injection). Keep the Hermes group to sites you trust, and keep Hermes's own approvals on for anything risky.
  • Pairing codes are 6 characters, expire after 5 minutes, at most 3 can be pending, and at most 10 can be requested per 10 minutes. Each approval through the agent asks you to confirm that exact code. An agent with shell access to the server could still call the relay's control socket directly; the relay can't stop software running as the same user.
  • Tokens are 256-bit random values. The server stores only their SHA-256 hash (devices.json, mode 600).
  • Don't put an interactive login page (like Cloudflare Access) in front of the relay's hostname. The extension can't complete it. Pairing is the access control.
  • Two input paths. Ref-based clicks/typing are scripted and some sites ignore them. The mouse action uses browser-level input through Chrome's debugger API. It does not move the operating-system cursor; a click-through page overlay shows where the agent is acting.

Limitations

  • One connected browser at a time (a new connection replaces the old one).
  • Some sites ignore scripted clicks/typing, and rich editors may not accept type.
  • screenshot brings the agent's tab to the front of its window.
  • Pages Chrome protects (chrome://, the Web Store) can't be scripted.

Foreground when useful (1.1.1)

Tab focus is a per-action choice, not a site-name heuristic. Use foreground: true when opening chats, demonstrating something, or showing the user a result. Leave it false/omitted for quiet background research. Existing active tabs are not forcibly hidden by a background open.

{"action":"open","url":"https://example.com/","foreground":true}
{"action":"open","url":"https://example.com/","foreground":false}
{"action":"focus","tab_id":123}

Foreground mode expands the shared tab group, activates the tab, restores a minimized window and requests window focus. It preserves normal/maximized state otherwise. focus only accepts shared tabs and never navigates. OS focus-stealing restrictions may still apply. Reload the extension and refresh the Hermes process/tool schema to use these options.

Visible pointer and panel scrolling (1.1)

The purple Hermes pointer marks mouse movement, dragging, clicks and scrolling. Clicks show a ring; scrolls show a direction arrow. It cannot intercept clicks or focus, stays out of snapshot text, and disappears after 2.2 seconds of inactivity. It is a visual indicator, not your desktop mouse. Fullscreen/top-layer elements or protected pages may hide it.

{"action":"scroll","ref":42,"direction":"up","pixels":600}
{"action":"mouse","kind":"wheel","x":700,"y":400,"delta_y":-600}
{"action":"mouse","kind":"move","x":700,"y":400}
{"action":"mouse","kind":"click","x":700,"y":400}
{"action":"mouse","kind":"drag","x":300,"y":250,"to_x":600,"to_y":400}

Mouse x/y are viewport CSS pixels, not desktop coordinates or raw screenshot pixels. Screenshots include viewport width/height: scale image coordinates to those dimensions if the image is resized or HiDPI. Take a fresh snapshot after scrolling; refs can change and chat apps may load older messages lazily. moved:false means scrolling did not move; mouse wheel success means input was dispatched, so verify the resulting snapshot. No-ref scroll remains document-only.

Upgrade both sides. Update the plugin and reload/re-enable the unpacked extension in chrome://extensions. Chrome may require approving the added debugger permission. Old Hermes processes may retain the old tool schema; start a fresh process/chat. No relay change is required. The source in extension/ has this update; release downloads may lag until a new release is published.

Tests

node --test tests/input.test.cjs
# Optional real isolated Chrome fixture; requires Chrome and Python websockets:
python -m pip install websockets
python tests/browser_test.py

Set CHROME_BIN if Chrome isn't on PATH. The fixture creates a disposable profile and never uses your personal Chrome. Command-level debugger mocks plus real Chrome protocol tests do not alone prove every site's behaviour; test the installed extension after reloading.
