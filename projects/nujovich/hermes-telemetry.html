overview

hermes-telemetry is a Hermes Agent plugin that records API and tool-call usage, including tokens, estimated cost, and latency. It enforces budget limits by notifying at a soft limit and blocking further tool calls at a hard limit; a breached cron-job budget also pauses that job.

  • Records usage in SQLite with WAL mode.
  • Provides `/stats`, `/budget`, and `/setup` surfaces.
  • Automatically syncs OpenRouter pricing.

Observability + budget guardrails for Hermes Agent

Budget enforcement + observability for Hermes Agent. A plugin that can stop a run from doing more work once it is over budget, not just report it afterwards.

A comprehensive telemetry plugin that captures real usage data, enforces budget limits, and provides detailed cost analysis for AI agent operations. Built for the Hermes Agent Challenge by Nadia Ujovich.

The differentiator: it can stop further work once a budget is breached — not just report it after the fact. Set a daily cap below current spend, and the next cron run's tool calls are blocked by the budget:

/budget set global daily 0.001 writes the cap to budget.yaml; current spend ($0.0102) already exceeds it, so /budget re-renders at 1020% [daily] — a hard breach — and the next marketing cron run is blocked by the budget.

Hermes Agent runs autonomously — across sessions, platforms, and cron jobs — which means it can keep spending even when you're not watching. hermes-telemetry lives inside the runtime, records every API and tool call, and enforces budget limits at the tool-call gate: once a hard limit is breached, every further tool call is blocked, and a breached cron-job budget also pauses that job. Hermes cannot abort a model call that is already in flight, so that response still completes and is billed — see Budgets for exactly what enforcement can and cannot stop.

This plugin targets a gap raised repeatedly in the Hermes tracker: budget enforcement for unattended runs — blocking further work once spend passes a cap, not just reporting it after the fact (see #23419 and #26382). It complements — it does not replace — the first-class telemetry work in #51714.

Your Hermes session
  ↓ every API call and tool call
hermes-telemetry (runtime-integrated plugin)
  → records tokens, cost, latency, and tool calls
  → injects a one-time notice at the soft budget limit
  → blocks every further tool call at the hard limit
  → logs to SQLite with WAL mode
  → syncs OpenRouter pricing automatically
  ↓
LLM provider and tools

Not a log reader. TokenTelemetry and similar tools read what already happened. hermes-telemetry hooks into the Hermes runtime and can stop what happens next.

Design principle: observability is invisible to the model. Everything goes through hooks. The only user-facing surfaces are /stats, /budget, and /setup.

Installation

Hermes plugins are opt-in — you must both install and enable the plugin.

hermes plugins install nujovich/hermes-telemetry
hermes plugins enable hermes-telemetry
hermes gateway restart

Prefer a manual install? git clone https://github.com/nujovich/hermes-telemetry ~/.hermes/plugins/hermes-telemetry and enable it the same way. Plugin changes only take effect after a gateway restart. The Installation guide covers the command-line tool, the dashboard plugin, and updating.

Quick Start

  1. Install and enable the plugin, then restart the gateway
  2. Run any session, then type /stats to see captured data
  3. Optionally review pricing.yaml and budget.yaml, which the setup wizard generates on first load

That's it. The plugin captures data automatically — no agent action required. Cost is always an estimate computed from a local pricing table; see What it measures.
