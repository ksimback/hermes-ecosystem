overview

LitHermes is a plugin for Hermes Agent that structures work around goals, plans, tests, reviews, and handoff notes. It can track whether checks are complete, flag stale test evidence, and offer unfinished goals to a later session; it works with Hermes CLI and Telegram or Discord gateways.

  • Adds goal criteria, test evidence, and review checks to sessions.
  • Writes handoff cards under `.hermes/lithermes/handoff/`.
  • Hermes Desktop pane is available in version 0.23 or later.

LitHermes

Keep the work lit.

A plugin for Hermes Agent that helps every session plan the work, build it, check it and leave a note the next session can pick up.

Put lit in front of a request and Hermes pins what "done" means, writes a test that fails before the change, checks the running result and writes down where things stand. With lit on, you see this:

  • A "done" that has to be earned. When a reply says it is done while the goal's checks are still open, it ends with ⛔ LIT: not done — <reason> and the goal will not close. A lit session that says done without ever opening a goal gets the same line, with that reason.
  • Tests you can trust. A green counts only when the plugin watched that test command finish with exit 0 and signed a receipt for it. Change the code afterwards and the receipt goes stale until the tests run again. Delete a test, drop an assertion or add a skip, and the goal stays closed until you accept the change yourself with /lit-accept-tests <reason>; the model has no way to do that.
  • A note for tomorrow. When a session that held a goal closes, a handoff card is written under .hermes/lithermes/handoff/. The next session in that project offers the unfinished goal, and a bare lit picks it up.
  • A pane in Hermes Desktop. The goal, whether its gate is open and a six-step timeline sit in a right-hand pane. It is Off by default: in Hermes Desktop 0.23 or later, switch LitHermes on under Capabilities > Plugins.

It works the same in the Hermes CLI and through a Telegram or Discord gateway. To try it, install once, restart Hermes and give it a task:

npx --yes --package @litfamily/lithermes@latest -- lithermes install --yes --no-style

lit fix the failing login test

Why LitHermes

Hermes Agent is good at the task in front of it. Work that outlasts one sitting is harder: the conversation gets compacted, the terminal closes or the gateway restarts, and next time you first have to work out what was decided, what was really tested and what was left half done. And "done" often means only that the model said so.

LitHermes gives each session a routine and keeps a record of it. With lit in front, a request gets criteria you can check, a test that fails before the change and passes after it, a look at the running result, and a handoff note in your project. For a bigger change, lit plan writes a plan you approve before anything is edited. Goals, plans and evidence stay on disk, so a fresh session reads them and carries on. Hermes still runs the model, the tools and your sign-in; LitHermes adds the way of working on top. LitHermes suits people who already use Hermes on work that has to hold up: code that must keep passing its tests, reports and decks that go to other people, research you want sources for. It helps most when the work outlasts one sitting, or when you start it at your desk and check on it later from a phone through a gateway.

Install

You need Hermes Agent, Node.js 18 or later, and write access to your Hermes home (normally ~/.hermes). This page describes @litfamily/lithermes@1.0.40. Run this in any terminal:

npx --yes --package @litfamily/lithermes@latest -- lithermes install --yes --no-style

The installer copies the Python plugin into your Hermes home and switches it on in config.yaml, after saving a backup of that file. On a fresh home it also writes the model routes LitHermes is tuned for, one for planning and review and one for helpers; a model you already chose is kept. It adds the Ignition skin and twelve more LIT skins. --yes runs it without stopping to ask, and --no-style skips the question about reply wording. Then restart the Hermes CLI and any running gateway: Hermes loads a new plugin only when it starts.

Captured from the real installer in a scratch Hermes home, run offline so nothing left the machine; some lines are cut. More screens are in the tour.

If you would like to look first, install --dry-run prints every change and writes nothing. To keep your everyday setup untouched, point HERMES_HOME at a new, empty directory before you install and start Hermes with the same value; model routes may then show as unavailable, and lithermes doctor --offline is the check that tells you the plugin is in place. Every flag, the trial profile and installing from a reviewed .tgz.

Extensions

LitHermes's core is complete and works on its own: planning, loops, goals, reviews, research, handoffs and prose cleanup all ship in this package. Nine skills that make files are LitFamily extensions, kept on the extension shelf wjgoarxiv-skills. Install the ones you use alongside LitHermes to get the full LitFamily experience: lit-pptx for decks, lit-docx for documents, lit-diagram-drawer, lit-schematic and lit-scientific-visualization for figures, frontend-ui-ux and visual-qa for design, and lit-typographic-motion and readme-studio for video covers.

Inside the package are 31 core skills, from litwork and lit-plan to review-work, lit-handoff and lit-humanizer, and every lit route runs on them. Each of the nine extensions left only a stub with its name in the package. The picture shows both parts, the five families on the shelf, and the four steps that bring one extension into your profile.

Each extension has a Hermes edition, one self-contained folder under variants/lithermes/. Clone the shelf once, copy the folder of the skill you want into your Hermes profile, then start a new Hermes session:

git clone https://github.com/wjgoarxiv/wjgoarxiv-skills.git
mkdir -p "${HERMES_HOME:-$HOME/.hermes}/skills"
cp -R wjgoarxiv-skills/variants/lithermes/<id> "${HERMES_HOME:-$HOME/.hermes}/skills/"

The copy sits beside LitHermes in the profile's skills/ folder, so upgrades and uninstalls leave it alone. Until you add one, its name still answers: /lit-pptx, or lit with a request for a deck, tells you it is an extension and gives you the lines above. The installer prints this note after an install or an upgrade, and the first Hermes reply after that shows it once more. After an upgrade from an older release, the note also names the tool caches the old film, deck and Word skills left behind (lithermes/motion/ and lithermes/office/ in your cache folder) and the update backups that still hold those skills; you can delete them if you do not install those extensions.

Quick start

Restart the Hermes CLI or gateway so it loads the plugin, then hand it one small task with lit in front:

lit Build a to-do list in one HTML file without external dependencies. Implement add, complete, and delete; record what you checked and what remains.

If you prefer commands, /lit <request> does the same. Telegram does not allow a hyphen in a command name, so on a Telegram gateway the plan and loop commands are /lit_plan and /lit_loop.

The reply opens with a line of its own, 🔥 **LIT IGNITED · <discipline>** 🔥, naming the route that took the request: litwork for a plain lit, lit-plan for a plan. It means the workflow has started; judge how it went from the result. When the task is done, open the HTML file, try each action yourself, and ask Hermes to separate the checks it ran from anything still unverified.

Then type /lit-handoff. The result and the next step go into HANDOFF.md in the project. Closing the session stops the work, and that file is how it continues: next time, open a new session in the same project and ask Hermes to read the handoff before it carries on.

The workflow map

In the terminal a Hermes plugin cannot add a panel or a status bar segment of its own (the Desktop pane above is the exception), so LitHermes shows where the work stands inside the reply itself. While a plan is being worked through, each reply ends with one map row:

🔥 LIT · lit-loop — 📝 plan ✓ › 🔨 WORK ▰▰▰▱▱▱▱ 3/7 › 🔍 · › 🏁 ·

Read it from left to right. After LIT · comes the workflow, then its four stages: a stage behind you carries a tick, the one you are in is in capitals with a gauge and a count of finished rows, and a dot marks a stage not reached yet. LitHermes builds the row from the plan, the run and the litgoal criteria saved in your project, so it keeps up without the model reporting each step. A stage with nothing saved is left out, and file names and commands never appear.

The Hermes CLI gets a look of its own as well. The Ignition skin greets you with the small LIT mark and LIT ready, says stay lit when you leave, and draws the banner in orange, lime, ivory and navy:

Captured from a real Hermes session with the Ignition skin selected. The Hermes banner, tip and warnings between the pictured lines are cut.

While Hermes works, the spinner turns in flame faces such as (🔥 lit) with short verbs like lit-looping and verifying, and /agents shows the helpers Hermes sent out with delegate_task. A fresh interactive install picks Ignition only when you have no skin set; lithermes hud lists the others, and /skin lithermes-tokyonight-day reads well on a light terminal. If you step away during long work, add --bell to the install and Hermes rings the terminal bell when a turn ends; it stays off otherwise, and a display.bell_on_complete value you chose is kept. Gateway messages never show the CLI skin. The skin, the marks and the film.

Automatic handoff

A long session fills the model's context window, and when Hermes compacts it, older detail is lost. Automatic handoff has the model write the handoff before that point; you then run /compact, and the rest of the session starts from a written record. It is off by default, and you pick the percent yourself, since LitHermes has no built-in value. The choice is saved in your Hermes home at ~/.hermes/lithermes/auto-handoff.json, so it follows you from project to project.

To switch it on, type /lit-handoff auto on 60 inside a Hermes session, with any whole number from 1 to 99 in place of 60. The reply says what will happen and compares your percent with the point where Hermes would compact on its own. Later, /lit-handoff auto status shows the latest reading for the session, and /lit-handoff auto off switches it off and remembers your percent for next time.

Once a model call passes your percent, your next message carries a short request to write a handoff. The model saves HANDOFF.md, tells you Handoff saved. Run /compact now. and carries on. A Hermes plugin cannot start a compaction, so /compact stays with you. Afterwards, your next message brings a short digest of that handoff back to the model, and the work picks up where it stopped.

To have it on in every session, set LITHERMES_AUTO_HANDOFF=1 and LITHERMES_AUTO_HANDOFF_PERCENT=60 where Hermes runs, for example in your shell profile; they win over the slash command. Keep the percent below Hermes' own compaction point, and doctor warns you when it is not:

Automatic handoff goes through each step and says who does it.

What you get

LitHermes installs 40 skills, their slash commands and the goal_* work tools. Most days you will use a handful, each started with a word or two.

A task that ends checked

A plain lit keeps a notepad and takes each criterion through the same loop: a failing test, a passing one, a check against the running result, then cleanup. You get the change and a list of what was verified. Typing lit again in the same session carries on in the mode you are in, and lit new … starts fresh.

lit fix the failing login test

Plan first, then build

lit plan writes a plan file with numbered task rows and leaves your code alone. Read it, and when it looks right, run /start-work with the plan file; it runs the plan row by row and ticks a box only after all five gates pass. Right after a plan is saved, a bare go in the same session shows you that exact command to run.

lit plan add CSV export to the reports page
/start-work <the plan file it wrote>

A second look before you merge

lit review has two modes. A plan review checks a plan after lit plan and before start-work. A work review hands the finished change to five reviewers who read it separately, and each one leads with what it found; fixing comes after. It picks the mode from what exists in your project, says which one on its first line, and lit review plan or lit review work forces one.

lit review the changes on this branch

Research with sources

lit research splits a question, sends searchers out in parallel and follows every lead before it answers. Each claim comes back with its source, anything it fetches is read as plain data, and it stops at logins and paywalls.

lit research how do popular CLIs migrate old config files?

Korean and English prose

humanizer rewrites stiff Korean or English prose, keeps the facts, hedges and register, and leaves your files alone until you decide.

humanizer 이 문단을 자연스러운 한국어로 다듬어줘: …

Ideas before a plan

For an open question such as a name or a direction, lit brainstorm lays out many different options first, then a short list with the trade-offs. You pick, and it hands the pick to an interview or to lit plan. It never builds anything itself.

Bring in a technique you read about

You read an article or a repository that does something your own skill does not. lit hijack records where each source came from, checks its licence, writes a spec in its own words, builds it through Hermes helpers, and proves the change by running the old and the new skill on the same prompt.

lit hijack https://example.com/post into my lit-humanizer skill

Where was I?

After a day of several windows, lit adhd (or lit rewind) reads the recent Hermes sessions of this repository with their plans, handoffs and git history, and gives you a board: 🎯 the one thing to do now with the exact text to type, 📊 done / in progress / waiting on you / left counts with an overall bar, 🏁 each plan's progress, ✅ what finished lately, ⬜ what is still to do, and 🔔 reminders such as a session waiting on your answer, uncommitted changes, or a plan nobody touched for a week. It changes nothing. If its next step is what you want, answer go within half an hour; while other sessions are still at work, it tells you to wait for them. Add detail (lit adhd detail) for the per-session brief pictured above, under the board.

From a phone, through a gateway

Every route above also works through a Hermes gateway such as Telegram or Discord, so you can start a plan at your desk and check on it from a phone. A gateway loads a new or updated plugin only when it restarts, and lithermes doctor tells you when the running one is older than your last install.

How it works

LitHermes is a Python plugin. When Hermes loads it, register(ctx) adds hooks, commands, skills and work tools. The hooks step in just before and after each model or tool call. The goal_* tools write your goals, and the evidence gathered for them, to local records in your project.

The picture follows one request from the moment you type it. A prompt that starts with lit and a slash command such as /lit-plan both arrive at the same place, where the pre_llm_call hook or the registered command picks a discipline: litwork for a plain lit, lit-plan for a plan, and so on. From there the skill works the goal through the goal_* tools, and every terminal command it runs is noted and signed by the post_tool_call hook. A work review sends five delegate_task reviewers that read the change on their own. Before the reply goes out, pre_verify and transform_llm_output check the gate. With the gate open, "done" stands. With the gate closed, the reply ends with ⛔ LIT: not done and the reason. Everything on the right side of the picture is a file in your project, and the dashed line is why a fresh turn knows where the work stands: the goal record is read back before every model call.

The same route, drawn as a plant

The same route works as a small process plant, and the plant shows something the boxes above hide: work goes round. The request comes in on the left. A plain lit runs straight into the work unit, while lit plan stops at the plan unit first. Finished work passes the review column, whose five trays are the five reviewers, and then the gate, which acts as an analyser on a three-way valve. A passing reply leaves as done. A failing one goes back to the work unit as LIT: not done, and it keeps going round until the gate opens. Run notes and review receipts drain into the records tank, .hermes/lithermes/ in your project. The tank sends the goal snapshot back to the router on every turn and the handoff card on to the next session. The stream table says what each numbered line carries and which hook or tool carries it.

Before the next model call, the context hook reads those records and hands the model the current goal and how far it has got. A plain prompt that starts with lit is routed by the plugin; a slash command goes straight to its skill. Text you paste in, from code to copied commands, is read as data and never followed as an instruction. The plugin decides where a request goes, and Hermes Agent still runs the model. Permissions, sign-in, model access and anything that needs a real screen stay with Hermes.

Requirements, updates and removal

LitHermes needs Hermes Agent 0.21.3 or later, Node.js 18 or later, and write access to your Hermes home. The skills that make films, decks and Word files moved to wjgoarxiv-skills with the tools they need, so LitHermes itself needs nothing more.

Two places on your machine hold LitHermes, and they fill up at different times. The installer writes only into your Hermes home: the plugin folder, the switch in config.yaml (after it saves a backup), the skins and its own install record. Your project stays untouched until you work in it; then the plugin keeps its goals, run notes and handoff cards under .hermes/lithermes/. Extensions you copied into skills/ sit beside the plugin, and an upgrade or an uninstall leaves them alone. An automatic update follows the bottom row of the picture. It always takes a backup before it installs anything, and if the new version fails its offline check, the backup goes back.

It keeps itself up to date. When you run install, check or doctor in a terminal, or send the first message of an interactive Hermes CLI session, it looks for a newer stable release, backs up your plugin and settings, installs it and runs doctor --offline; if anything fails, the backup goes back. Gateways and the full-screen TUI never update this way. To install updates yourself, set LITHERMES_NO_AUTO_UPDATE=1. Updates lists every step and switch.

Its records stay on your machine. Goals, plans, evidence, signed run notes and handoff cards live under .hermes/lithermes/ in your project; the install record, update cache and backups live in your Hermes home. Four details are worth knowing. A run note shows that the plugin saw a command finish with that exit code, and it does not show that the command tested anything useful. The test watch behind /lit-accept-tests keeps its counts in a project file that a model with a raw shell could empty. A new session reads other sessions' goal files in the same project to offer a resume, but only goals this install sealed with its own key (kept in your Hermes home), and LITHERMES_GOAL_RESUME=0 turns that off. A handoff card is written when Hermes closes the session, which can be well after your last message. LitHermes goes online for one thing of its own: it asks npm whether a newer version exists, which you can switch off with LITHERMES_NO_UPDATE_CHECK=1 or skip for one run with --offline. Your prompts go to whichever model provider Hermes is set up with, as before. Privacy and local records lists every file it writes, and what the plugin checks, reads and starts covers the rest: the run signature, the Desktop pane's read-only route, the processes it launches, the Hermes internals it reads and the one install-scan caution.

To check an install without going online, or to remove it:

npx --package @litfamily/lithermes -- lithermes doctor --offline
npx --package @litfamily/lithermes -- lithermes uninstall --yes

In an offline doctor run, loaded plugin reads PARTIAL, because offline it cannot ask Hermes which plugins it loaded; that is expected. If the installer made compatibility edits to your Hermes installation, add --rollback-patches when you uninstall so they are undone too. When something goes wrong covers missing skills, name clashes and import errors.

LitFamily

LitHermes belongs to LitFamily, the same lit way of working ported to seven coding agents. The seven armored robots on the cover stand for those seven products; each runs on its own in its own host, so install only the one you use. The cover is brand motion, and the Ignition film is a short brand film in the same spirit. The demo near the top of this page is the one that shows a real Hermes session.
